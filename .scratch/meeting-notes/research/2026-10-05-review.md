# Spec review, 2026-10-05

Independent review of the first draft of `../spec.md`, run through delegate on lane
`astra-xhigh@codex`. Read-only; it listed the model cache folder without reading files.
Verdict: not ready to implement as written. The revised spec addresses each finding.

## High

1. Cache reuse depends on the SDK version. Current FluidAudio `main` strips `-coreml`
   from folder names; the installed cache still has it and matches an older loader.
   Pin the SDK and model, pass an explicit directory, check compatibility.
2. A cache path is not an offline guarantee: `load(from:)` re-resolves the folder and
   the model hub can download or purge. Use `loadLocal` and the offline guard.
3. No diarizer assets on disk; `prepareModels()` downloads them. Add provisioning and
   a preflight; write an undiarized transcript or fail when missing.
4. Equal sample rates do not mean synchronized legs. Two processes start
   independently; mictee drops tap timestamps and inserts no gap after a device
   change. Record a common clock, sample counts, discontinuities; correct drift.
5. Channel layout needs a contract: mic ch0, system ch1, pad a missing leg, format
   version, legacy mono marked, lossless master with a derived listening mix.
6. "Me vs the room" overclaims: in-room voices and leakage reach the mic. Keep
   source apart from speaker; invitees never become speaker names.
7. Stage contracts and reruns: versioned manifest, stable ID, atomic writes, locks,
   fingerprints, invalidation, protect manual edits.
8. The trigger must wait for finalization (`onExit` after validation), with a
   persistent queue, no duplicate runs and visible states.
9. Partial recordings look successful today (non-empty file = healthy, exit status
   lost, salvage returns success, logs deleted). Record per-leg health; validate
   before cleanup.
10. Privacy has no runtime enforcement: notes off until a local model is set,
    loopback only, no telemetry or cloud fallback, private permissions, no content in
    logs, no synced folders, an egress test.

## Medium

- Long meetings: ~15 s ASR windows have seam errors; use the disk-backed diarizer,
  cap memory, checkpoint, test multi-hour audio, summarize in chunks.
- Evaluate `fluidaudiocli transcribe` and `process --mode offline` before writing a
  custom CLI; add only a thin adapter. The single-file `swiftc` Makefile pattern
  cannot build a package with dependencies.
- Alternatives: FluidAudio fits best first (upstream short-corpus figures: v2 2.1%
  WER, v3 2.5%). WhisperKit, whisper.cpp, sherpa-onnx and pyannote are fallbacks.
- Calendar: keep requested and actual times apart; ambiguity stays unmatched. Keep
  raw ASR text; filler removal is a derived view.

## Low

- Keep recordings, transcripts, logs and models outside the checkout; synthetic
  fixtures only.

## Not verified by the review

SDK version inside the installed VoiceInk build, an actual offline load, drift,
leakage, speed and memory.
