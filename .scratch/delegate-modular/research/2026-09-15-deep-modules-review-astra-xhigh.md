## Pass-through and speculative layers

- `chunk_packet = split_packet` exports another name without another behavior; the reviewed scripts/tests use `split_packet`, and the alias has no references in that set (`effort.py:830`, `test_effort.py:712`). Remove the unused alias unless an external consumer is established.
- `rank(..., effort=None)` advertises an override which it explicitly does not use or pass into `rank_range` (`rank.py:245`, `rank.py:252`, `rank.py:268`). Remove the unused parameter from this interface; effort selection belongs to Lane/dispatch handling.
- `ledger_finish` has one call site and mostly repackages arguments for `events.append(events.finish_event(...))`; its only added rule is a fallback exit code (`delegate.py:690`, `delegate.py:824`). Inline that composition when changing Run finalization. Do not introduce an event-service layer for it.
- `Wizard._mean` and `Wizard._discovery_notices` have no references in the reviewed scripts/tests (`setup_tui.py:599`, `setup_tui.py:1178`). The latter only forwards stored arguments. Remove these unused methods. Bound-argument helpers such as `_bench_order` and `_fit` are local conveniences; they do not justify new modules (`setup_tui.py:611`, `setup_tui.py:1089`).
- `ads.sh path` returns the relay filename, but dispatch reconstructs that filename itself (`ads.sh:51`, `delegate.py:441`). Choose one owner when tightening relay preparation; adding another forwarding function would preserve the duplication.
- `setup.show_bench` is a shallow process/file adapter around behavior already exposed in Python; it adds temporary catalog files, parses a human message and opens a generated report (`setup.py:118`, `setup.py:132`, `setup.py:138`; `bench.py:727`, `bench.py:623`).
- The four typed wrappers are thin, but they implement an actual entrypoint choice and prose filtering; the native Lane file supplies actual model/effort configuration (`agents/skills/delegate-codex/SKILL.md:10`, `agents/skills/delegate-codex/SKILL.md:18`; `agents/agents/lane-opus-high.md:2`). Likewise, courier has a stated Workflow host constraint, though its protocol needs to reject unsupported native handoffs (`agents/agents/courier.md:3`, `agents/agents/courier.md:15`; `delegate.py:768`).

## Leaks

- Presentation text acts as a policy discriminator: `propose_enabled` returns `(enabled, reason)`, and the page recognizes domination by finding `" wins on "` in that reason (`setup_tui.py:494`, `setup_tui.py:330`, `bench_page.py:178`). A prose edit can change which points count as proposed off.
- Benchmark decision failures are converted to an empty proposal map; the header can then claim that no carried Lane is beaten (`bench_page.py:166`, `bench_page.py:926`). Unavailable judgment and a successful judgment with no proposals need distinct results.
- Plain setup and the Wizard each implement the change from Tier lines to carried/Tier state, despite sharing the parser (`setup_tui.py:153`, `setup_tui.py:725`). Share the state transition, not just tokenization.
- Report code knows Meter cache envelopes, the event ledger path/schema and vendor token-key aliases (`report.py:44`, `report.py:535`, `report.py:565`, `report.py:600`). Move protocol interpretation toward the producing boundary; keep rendering and cost arithmetic in reporting.
- Setup knows the ADS discovery script location and parses its wire document, then separately asks `discover.discover` to infer presence again (`setup.py:31`, `setup.py:47`, `setup.py:302`; `discover.py:378`). Authentication/version discovery and model discovery are different observations; they should be distinguished by a discovery interface, not conflated or silently dropped.
